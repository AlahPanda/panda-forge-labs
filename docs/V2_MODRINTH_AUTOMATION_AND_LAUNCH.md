# V2 Modrinth automation and launch gate

Status: branch `v2/full-redesign`; **not a Production launch record**. The owner's approved slogan is provided in all four UI locales. Mac Native remains beta in editorial status; the upstream release channel is reported separately.

## Flow and boundaries

1. In `/admin/editor/modpacks`, **Connect Modrinth Project** accepts an official modpack URL, slug, or ID. The authenticated `admin-cms/modrinth-lookup` Edge action fetches the official project and versions. The owner reviews title, slug, current release and counts before preparing a V2 project. This is only local editor state until **Save private draft**. The existing Draft → Preview → Publish flow, branch guard, revision check and SHA check remain in force. A new or changed connection is checked again server-side on publication; duplicate project IDs/slugs are refused.
2. Published V2 projects with `upstream.provider=modrinth` use `/api/modrinth/:slug`. Only checked-in published projects are exposed. Modrinth `/v2/project/:slug` and `/v2/project/:slug/version` provide the project, current release by `date_published`, compatibility, changelog, icon, full gallery and real counts. Values are validated before use. The owner-written project description, features, translations, SEO and status are never overwritten by sync.
3. `modrinth_snapshots` holds the last valid response in Supabase, server-side only. Runtime freshness is 15 minutes. Every request after TTL attempts a refresh; failure serves the stored snapshot with `stale=true`. A malformed response cannot replace it. If persistence is not configured but upstream is reachable, live facts are served with `persistence=unavailable`. If neither upstream nor a stored snapshot is reachable, the API returns 503. The page and official project download destination still work; it does **not** show a fabricated zero or label historical release 0.3.1 as the latest.
4. `/api/download/:slug` redirects only connected published projects to the current official Modrinth release URL. On an upstream outage without a snapshot it redirects to that project's official Modrinth project URL. It never accepts a redirect URL from the visitor. Historical editorial articles and releases may retain historical links; main CTAs do not.
5. Premium and Basic are CMS options. Connected downloadable projects default to Premium. `premiumCopy` selects approved Mac copy or generic localized copy; future projects require no slug-specific React code. Optional `heroArtwork` has Day/Night desktop and mobile slots. The gallery uses all valid official CDN images, falls back to approved local media, advances every 3 seconds, pauses on interaction, disables autoplay under reduced motion and preloads the next image. No gallery is fetched on listing cards.
6. Global supporter download settings live in V2 Site Settings; a project can override or explicitly disable them. Only HTTPS links pass schema and runtime checks. With a configured link, an accessible dialog offers **Support & Download** and **Continue normally** equally. Without one, the normal download goes directly to the resolver. No URL is enabled by default.

## Configuration by environment

**Preview first.** In the Preview Supabase project, apply `supabase/migrations/20260929000000_modrinth_snapshots.sql` with the Supabase SQL Editor or the project's existing migration workflow. Keep RLS enabled. In Vercel → AlahPanda Labs project → Settings → Environment Variables, configure `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` for the **Preview** environment only, scoped to `v2/full-redesign` where Vercel offers branch scope. This service-role key is server-side; never prefix it with `VITE_`. Redeploy a Preview after adding variables. The client already uses its separate `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for owner authentication. Supabase `admin-cms` retains `ADMIN_PASSWORD`, `ADMIN_JWT_SECRET`, `ADMIN_ORIGINS`/`ADMIN_PREVIEW_ALIAS`, `GITHUB_TOKEN`, `GITHUB_REPO` and `GITHUB_BRANCH=v2/full-redesign`; do not change Production secrets for this Preview test. The server-side Modrinth lookup requires redeploy of this Edge Function in the Preview Supabase project.

In Vercel Production, **after** the release gates and authorized deployment, apply the same migration to the intended Production Supabase project and set its own server-side `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and a strong `CRON_SECRET` (Vercel → Settings → Environment Variables → Production). Vercel automatically sends `Authorization: Bearer <CRON_SECRET>` on its cron invocation. Never use the Preview service-role key in Production or vice versa. The daily `0 6 * * *` schedule targets `/api/sync-modrinth`. Vercel cron runs on the **Production** deployment only; a Preview branch cannot be tested via Vercel Cron. Preview uses the 15-minute runtime refresh and can validate `/api/modrinth/mac-native` manually. The schedule is daily for Hobby-compatible limits; runtime visits may pick up a release sooner. The exact invocation time is not a punctual guarantee.

If the migration or service-role configuration is missing, runtime fetching can still work, but last-known-good persistence cannot be guaranteed. Treat this as a launch blocker for automated release truth. Do not publish a new project from a draft until the Edge lookup and duplicate checks succeed.

## Owner workflow

Open the authenticated Preview `/admin`, log in, then visit `/admin/editor/modpacks`. Paste `https://modrinth.com/modpack/<slug>` into **Connect Modrinth Project** and select **Check official publication**. Review name, slug, latest version, gallery count and official page. Choose **Review as private draft**, add owner-authored editorial fields and optional Day/Night artwork, select Premium or Basic, save, inspect private Preview, then publish to the configured branch. Verify the commit and Vercel Preview deployment separately; a Git commit is not proof of deployment. To change supporter behavior, edit `settings/site` for the global default or the project's `supporterDownload` fields; save, preview and publish through the same path. Leave enabled off if no owner-approved HTTPS destination exists.

For a new upstream release, no CMS action is required after successful setup. Once a visit crosses TTL or cron refreshes the snapshot, version, release channel/date, loaders, Minecraft versions, gallery, counts and current release link change together. The project status such as `beta` is editorial and does not change merely because an upstream version number or release channel changes.

## Live acceptance checklist before Production

- Confirm the official Modrinth API responds to the Preview server and the snapshot is persisted. Confirm a second request reads it and an upstream outage returns `stale=true` with the same last valid release.
- After Mac Native 0.6.0 is actually published, verify the official version page, then wait at most the runtime TTL plus a visit or the next scheduled refresh. Confirm `/api/modrinth/mac-native` reports **0.6.0**, the website displays its real compatibility, date, gallery and counts, `/api/download/mac-native` points to its official current release, and the full changelog link points to that same release. Then publish 0.6.1 in a controlled test if available and verify all current links change without code or CMS edits. Do not fabricate a version or publish a test release solely to satisfy this checklist.
- Connect a different real test project via CMS Preview; check duplicate rejection, the same premium template, separate supporter override and publication. Delete the test draft if not approved as real content. Do not invent a public project.
- Verify login, draft, preview, branch commit, deployment readiness, core routes, responsive navigation, broken critical links, privacy/CMP and Support availability. Ads and support email must remain disabled when their required external configuration is absent.
- Only after the migration, secrets, live Modrinth end-to-end test and all critical product gates pass is Production release eligible. No merge or Production deployment is implied by this branch commit.

## Known limits

- The public Modrinth pages can show metadata, but this execution environment cannot connect directly to `api.modrinth.com`; the deployed Preview must perform the live end-to-end verification. 0.6.0 is a simulated test fixture until independently published.
- The current scheduled job checks Modrinth itself. Arbitrary external supporter shorteners are validated as HTTPS and remain owner decisions; automated outbound probing of these URLs was not added because it would create SSRF and false-negative risk.
- The client-side SPA's social metadata is generated by React Helmet; crawlers that do not render JavaScript may require a later prerender/server response. This remains a launch SEO review item.
