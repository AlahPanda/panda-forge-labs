# Support operations

## Support form activation, Preview only

The new `/api/support` Vercel Function is routed ahead of the SPA rewrite and accepts POST only from the same HTTPS origin. It validates category/email/subject/message, rejects missing/wrong Origin, checks a honeypot and Cloudflare Turnstile **server-side including the expected hostname**, calls an atomic Supabase RPC quota of three submissions per IP fingerprint per hour, then sends plain text through the Resend email API to `AlahPandah@gmail.com`. It returns generic errors and never exposes server credentials. IP fingerprints are HMACs using the server service-role key, not raw IP. Email is only sent after all checks. The UI keeps `mailto:` available. There is no real email delivery claim until the owner configures and verifies the provider.

1. In **Cloudflare Dashboard → Turnstile → Add widget**, create a widget for the actual Preview branch alias and any exact Preview deployment hosts you intend to test. Record the site key and secret separately. Add `VITE_TURNSTILE_SITE_KEY` in **Vercel → AlahPanda Labs → Settings → Environment Variables → Preview**, scoped to branch `v2/full-redesign` where available. Never select Production.
2. In **Resend Dashboard → Domains**, verify a sender domain you control (DNS records and status). Create an API key scoped for sending and choose `SUPPORT_FROM_EMAIL` from that verified domain. `AlahPandah@gmail.com` is the recipient, not a verified sender. In Vercel Preview branch env set `RESEND_API_KEY` and `SUPPORT_FROM_EMAIL`, with no `VITE_` prefix.
3. Apply `supabase/migrations/20260928_support_rate_limit.sql` to the **isolated Preview Supabase project**. This creates `support_rate_limit` with RLS and a service-role-only RPC. In Vercel Preview branch env set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` for that same Preview project, and `TURNSTILE_SECRET_KEY` from the widget, all server-side only. Do not copy these values into a public `VITE_` variable or Production. Supabase's Edge secrets and the Vercel Function env are separate configuration surfaces.
4. Create a new **Preview** deployment of this branch. Visit its `/support` page, submit a test message and confirm delivery in Resend logs and the inbox. Check missing challenge, wrong origin, repeated submissions and failure fallback. If the public site origin changes, update the Cloudflare widget allowed hostnames, not the server's same-origin rule.
5. Retention and data controller details require owner/legal review before Production. The quota table has no automatic cleanup; schedule periodic deletion of rows older than 48 hours in the Preview database, and set an operational retention policy before activation at scale.


Advertising and analytics remain disabled pending the owner gate in [MONETIZATION_PREVIEW_GATE.md](MONETIZATION_PREVIEW_GATE.md). Real email delivery still requires provider configuration and an owner test. No environments or secrets are changed by repository cleanup.
